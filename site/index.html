Chaff

never let him cook unsupervised.

Chaff is a desktop app for reviewing what Claude Code and Codex wrote, before you're about to crash out over a ten-MR stack. Local branches, GitLab MRs, GitHub PRs.

Install View on GitHub

how it goes

  1. 01 Pick the stack

    Walk the stack, see what builds on what, start a review. That freezes a snapshot, so the agent can keep cooking and the code you're reading stays put.

  2. 02 One card at a time

    G looks good, C concern, Q question, S skip with a reason. Skipping isn't approving: the reason ends up in the export, so the agent knows what nobody read.

  3. 03 Hand it back

    Findings turn into a prompt for Claude Code or Codex. Or hit Fix with agent and let it fix them in its own checkout.

  4. 04 "fixed", allegedly

    The agent pushes. Chaff says "1 new commit" and doesn't touch the code you're reading. Update brings back only what changed, right next to your concern. V once it's actually fixed.

ngl, my review process was mostly tab management

Claude Code and Codex made writing code cheap. Reading it didn't get any cheaper, and the merge request UIs were not helping.

  • Every MR thinks it's the main character. Ten stacked MRs, ten separate pages. By MR 6 I'm opening tabs to find out which one added that helper.
  • The famously fast MR viewer. Big diff? "Load diff". Bigger diff? "This diff is too large to display". Click a file, watch the spinner, scroll, and it collapses again. Truly the fastest way to review code.
  • The agent pushes mid-review. The page reloads, the diff regenerates, my place and the "viewed" checkboxes are gone. Glad somebody's making progress here.
  • Source: the agent said "fixed". Now I get to dig through three force-pushes to see if it fixed the thing or just agreed with me.
  • Everything is equally important. Import shuffles, renames and the one function that can eat user data, all in the same wall of green.

Could be a skill issue. I built Chaff anyway: code that holds still, concerns I can find again, and a second pass that only shows what changed. The first time I verified a fix without opening four tabs:

what it actually does

Snapshots that stay put

Starting a review pins the branch in Chaff's own git store. Rebase it, force-push it, delete it. Your review doesn't care.

One function at a time

A card is a whole function or type with the changes marked. G looks good, C concern, next.

A reading order that makes sense

Types and contracts first, tests next to the code they test, config and generated files last.

Findings with receipts

Concerns are pinned to the code and looked for again after every push. "Done" is the agent's opinion; you still check.

Second pass, only what moved

Unchanged code keeps your decision. Edited cards show what changed since you decided.

Hand it back

Export findings as a prompt, post them as GitLab or GitHub drafts, or let the agent fix them in a separate checkout.

Optional AI digest: your local Claude Code or Codex reads the branch first and leaves notes on each card. It doesn't get a vote. Every decision is still yours.

fine print

  • It's early. Things move around, sometimes a lot.
  • Builds are unsigned (I will not be paying for a license for a side project), so you build it from source. Takes a few minutes.
  • There's no updater. There's git pull. More on that below.
  • Read-only on your repo: Chaff reads with your own git and writes only to its own store. No checkouts, no new refs, no stash.
  • No account, no server. Reviews live in a SQLite file on your machine.

install

You need Git 2.40+, Node.js 24 and pnpm 11.5 (corepack enable sets it up).

macOS 
git clone https://github.com/CatOfJupit3r/chaff.git
cd chaff
pnpm install
pnpm run install-app

Builds Chaff and puts it in /Applications.

Windows and Linux 
git clone https://github.com/CatOfJupit3r/chaff.git
cd chaff
pnpm install
pnpm run package

The installer lands in apps/desktop/release. SmartScreen will complain about the unsigned build: More info, then Run anyway. On Linux, chmod +x the AppImage and run it.

updating

On macOS it's just git pull. install-app leaves a git hook behind, so every pull on main rebuilds Chaff in the background, swaps it into /Applications, reopens it if it was running and sends a notification when the new build is in. Don't want that? git config chaff.autoInstall false.

macOS 
git pull
Windows and Linux 
git pull
pnpm install
pnpm run package

Then run the new installer from apps/desktop/release. Your reviews stay where they were.

or make the agent do it

Paste this into Claude Code or Codex and go touch grass while it builds.
