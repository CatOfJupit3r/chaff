# Best Practices

Critical best practices for TanStack Query with oRPC.

## 1. Always Use useQueryClient(), Never Import a QueryClient

**Don't**: Import or create a QueryClient for mutation callbacks

```typescript
import { queryClient } from '@~/utils/query-client';

mutationOptions({
  onSuccess: () => {
    queryClient.invalidateQueries({ ... }); // WRONG
  },
});
```

**Do**: Get the client from `useQueryClient()` in the hook that builds the options

```typescript
export function useRemoveWorkspace() {
  const queryClient = useQueryClient();

  return useMutation(
    tanstackRPC.workspaces.remove.mutationOptions({
      onSuccess: async () => {
        await queryClient.invalidateQueries({ queryKey: tanstackRPC.workspaces.key() }); // CORRECT
      },
    }),
  );
}
```

**Why:** The `QueryClient` is created in `createAppRouter()` (`router.tsx`) and reaches components through `QueryClientProvider` and loaders through `context.queryClient`. There is no module-level instance, so a test or a second router never shares a cache by accident.

---

## 2. Take Output Types from ORPCOutputs

Declare a feature's output types once, in its `*.types.ts`:

```typescript
import type { ORPCOutputs } from '@~/utils/orpc';

export type iWorkspace = ORPCOutputs['workspaces']['list'][number];
export type iBranch = ORPCOutputs['workspaces']['branches'][number];
```

Keys generated by oRPC carry their data type, so cache reads and writes need no type argument:

```typescript
const previous = queryClient.getQueryData(settingsQueryOptions.queryKey); // typed as the settings output
queryClient.setQueryData(settingsQueryOptions.queryKey, settings);
```

**Benefits:**

- IDE autocomplete in cache updates
- Type-safe cache manipulation
- Catch errors at compile time

---

## 3. Always Export Query Options

Never inline query options that something else reuses. Export them for:

- Route loaders (prefetch)
- Mutations (cache updates)
- Tests

```typescript
// Export query options
export const settingsQueryOptions = tanstackRPC.settings.get.queryOptions();

// Use in hook
export function useSettings() {
  return useSuspenseQuery(settingsQueryOptions).data;
}

// Use in loader (routes/__root.tsx)
loader: async ({ context }) => context.queryClient.ensureQueryData(settingsQueryOptions),

// Use in mutation
queryClient.setQueryData(settingsQueryOptions.queryKey, settings);
```

Options that take an input become a function of that input:

```typescript
export const branchesQueryOptions = (workspaceId: string) =>
  tanstackRPC.workspaces.branches.queryOptions({ input: { workspaceId } });
```

---

## 4. Use Generated Query Keys, Never Manual Keys

**Don't**: Create query keys manually

```typescript
const key = ['workspaces', 'branches', workspaceId]; // WRONG
```

**Do**: Use generated keys from tanstackRPC

```typescript
const key = tanstackRPC.workspaces.branches.queryKey({ input: { workspaceId } }); // CORRECT
const everyWorkspaceQuery = tanstackRPC.workspaces.key(); // partial key for the whole namespace
```

**Why:** Guarantees consistency with server contracts. Manual keys lead to mismatches.

---

## 5. Handle Undefined Cache Gracefully

Always check before accessing cache:

```typescript
queryClient.setQueryData(key, (oldData) => {
  if (!oldData) return oldData; // Important
  return { ...oldData, ...updates };
});
```

**Scenario:** Query hasn't run yet, cache is undefined. Gracefully handle this.

---

## 6. Prefer onSuccess over onSettled When Server Returns Data

```typescript
// If endpoint returns updated data
mutationOptions({
  onSuccess: (settings) => {
    queryClient.setQueryData(settingsQueryOptions.queryKey, settings); // Use server response
  },
});

// If endpoint does NOT return updated data
mutationOptions({
  onSettled: async () => {
    await queryClient.invalidateQueries({ queryKey: tanstackRPC.workspaces.key() }); // Refetch
  },
});

// If you need to run logic regardless of success/error
mutationOptions({
  onSettled: () => {
    // Runs after both success and error
  },
});
```

**Difference:**

- `onSuccess`: Runs only if mutation succeeds
- `onError`: Runs only if mutation fails; report it with `showToast(getErrorMessage(error))`
- `onSettled`: Runs regardless of outcome

---

## 7. Combine Optimistic Updates + Server Response + Error Rollback

```typescript
tanstackRPC.settings.update.mutationOptions({
  // 1. Update UI immediately (optimistic)
  onMutate: async (changes) => {
    await queryClient.cancelQueries({ queryKey: settingsQueryOptions.queryKey });
    const previous = queryClient.getQueryData(settingsQueryOptions.queryKey);
    if (previous) {
      queryClient.setQueryData(settingsQueryOptions.queryKey, {
        ...previous,
        ...settingsSchema.partial().parse(changes),
      });
    }
    return { previous };
  },

  // 2. Use server response (most accurate)
  onSuccess: (settings) => {
    queryClient.setQueryData(settingsQueryOptions.queryKey, settings);
  },

  // 3. Rollback on error
  onError: (error, _changes, context) => {
    if (context?.previous) queryClient.setQueryData(settingsQueryOptions.queryKey, context.previous);
    showToast(getErrorMessage(error));
  },
});
```

**Result:**

- Instant UI (onMutate)
- Server-accurate (onSuccess)
- Error recovery (onError)

---

## 8. Prefetch Route Data Before Navigation

Use route loaders to eliminate loading states:

```tsx
// routes/index.tsx
export const Route = createFileRoute('/')({
  loader: async ({ context }) => context.queryClient.ensureQueryData(workspacesQueryOptions),
  component: ReviewsScreen,
});

// Component renders instantly with cached data
export function ReviewsScreen() {
  const workspaces = useWorkspaces(); // Already cached!
  // ...
}
```

`createAppRouter()` sets `defaultPreload: 'intent'`, so loaders also run when a link is hovered or focused. Queries default to `staleTime: 30s`, `retry: false` (the core is local, so failures are not transient), and `refetchOnWindowFocus: true`. `ensureQueryData` returns cached data that is still fresh and shares one request between concurrent callers.

---

## 9. Type-Safe Inputs and Outputs

Use the generated types from contracts:

```typescript
import type { ORPCOutputs } from '@~/utils/orpc';

// Output types
type iBranch = ORPCOutputs['workspaces']['branches'][number];

// Inputs are typed at the call site by the contract
tanstackRPC.workspaces.branches.queryOptions({ input: { workspaceId } });
removeWorkspace({ workspaceId: workspace.id });
```

---

## 10. Name query options in camelCase

```typescript
// Query options
export const workspacesQueryOptions = tanstackRPC.workspaces.list.queryOptions();

// Query options that take an input
export const branchesQueryOptions = (workspaceId: string) =>
  tanstackRPC.workspaces.branches.queryOptions({ input: { workspaceId } });

// Keys come from the options (`workspacesQueryOptions.queryKey`) or from `.queryKey()` / `.key()`,
// and mutation options are built inside their use<Action> hook, so neither needs its own constant.
```
